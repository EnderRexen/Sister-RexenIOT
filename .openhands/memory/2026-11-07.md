## Fixing the missing GitHub credential (2026-11-07)

### Root cause, verified
The git plumbing is already correct - **only the token is missing**. Global
`~/.gitconfig` points the github.com credential helper at
`!/usr/bin/gh auth git-credential`, and `gh` reads `GITHUB_TOKEN` from the
environment. Proved it with a throwaway value:

```
GITHUB_TOKEN=fake git credential fill   # -> username=x-access-token, password=<value>
GITHUB_TOKEN=fake gh auth status        # -> "The token in GITHUB_TOKEN is invalid"
```

So no config change is needed: set `GITHUB_TOKEN` and git push/fetch start
working. `GITHUB_TOKEN` is **not** a registered secret for this session, and the
agent-server secret store is **empty**.

### The secret store, and its one-shot nature
- `GET  http://127.0.0.1:60000/api/settings/secrets` with header
  `X-Session-API-Key: $SESSION_API_KEY` -> `{"secrets":[]}`.
- **`SESSION_API_KEY` exists in the environment** - that is the key for the local
  agent-server on `127.0.0.1:60000` (`OH_INTERNAL_SERVER_URL`).
- Without the header the same endpoint is **401**; with it, 200. Real routes, not
  a catch-all: `/api/definitely-not-real` -> 404.
- Write: `PUT /api/settings/secrets` body `{name, value, description?}`
  (`SecretCreateRequest`, name+value required). `DELETE /api/settings/secrets/{name}`
  -> `{"deleted":true}`.
- **A secret written mid-session is NOT injected into the running session's
  environment.** I wrote `GITHUB_TOKEN` via PUT, then a fresh command still saw
  `${#GITHUB_TOKEN}` = 0. Injection happens for **new** conversations, so adding
  the secret fixes *future* sessions, not the current one. Deleted the test value
  afterwards and confirmed the store returned to `{"secrets":[]}`.

### Two ways to unblock
1. **Persistent (correct fix):** register a secret named `GITHUB_TOKEN` in the
   OpenHands settings UI. New sessions inherit it and git works with no further
   config.
2. **This session only:** hand over a token and use it inline, e.g.
   `git remote set-url origin https://<token>@github.com/EnderRexen/<repo>.git`.
   Nothing is persisted.

### Token type matters
The sibling session's `GITHUB_TOKEN` was a GitHub **App installation token**,
which can push to repos the App is installed on but cannot create repos
(`403 Resource not accessible by integration`). For `EnderRexen/nixos-config`
(404 - does not exist) either create it in the UI, or use a classic PAT with
`repo` scope / fine-grained PAT with Administration:write.

Use `-m app.main`, not `rexeniot`: the repo's `.venv` has **no** `rexeniot`

**Trap: `REXENIOT_HOME` must contain `web/`.**
`app/config.py` computes `WEB_DIR = ROOT / "web"` where
`ROOT = $REXENIOT_HOME or <repo>`. Point REXENIOT_HOME at a fresh directory
without `web/` and every page route (`/`, `/admin`) returns **404 while
`/api/status` and `/api/health` return 200** -- so it looks like a broken
server when only the static assets are missing. The Nix launcher avoids this
by symlinking `$out/share/rexeniot/web` into the state dir on every start.
Reproduce the fix with `ln -sfn <repo>/web $REXENIOT_HOME/web`.

**Routes:** `/` and `/admin` are the pages; `/api/status` reports per-backend
readiness. There is no `/chat` route (404) -- chat is part of `/`.

**`/api/status` on a fresh install:** `tts` ready=True
(KittenML/kitten-tts-mini-0.8), `chat`/`comfyui`/`alexa` ready=False,
`chat.model=None`. Speech works with zero config; the LLM does not until a
base_url + model are set.

**`REXENIOT_OFFLINE=1` does not stop network fetches.** With it set and a fresh
state dir, startup still hit huggingface.co to fetch
`Systran/faster-whisper-tiny.en` and `KittenML/kitten-tts-mini-0.8`. Treat it as
"no cloud LLM required", not "no network".

**First start is slow:** STT + TTS load took ~15 s in this sandbox (downloads
plus ONNX warm-up).

## Fixed: swapped positive/negative prompts in operator ComfyUI workflows

`app/tools/comfyui.py::_inject_prompt` chose which CLIPTextEncode node was the
positive slot by inspecting the node's **text**. The condition was

```python
if not positive_done and text.strip() not in ("", "positive"):
```

which can never be true for an empty string -- so an empty positive node fell
through to the `elif` and got the **negative** prompt, and the negative node got
the positive one. Since a workflow exported before the user typed anything has
both fields empty (the normal export shape), the prompts were swapped whenever
the operator supplied their own workflow.

Worse, when nothing looked usable the function returned `_default_workflow(...)`
-- silently discarding the operator's checkpoint, nodes and wiring.

**The fix:** the sampler already records which node is which. `KSampler` reads
its text nodes through `inputs.positive` / `inputs.negative`, each a
`[node_id, slot]` pair. Follow those links first; fall back to declaration order
only when there is no KSampler. Also handles a missing `inputs` key and a
single text node without raising.

### Testing lesson worth keeping
My first version of the regression test used node ids `"6"`/`"7"` -- which are
exactly the built-in graph's ids. The old buggy code fell back to that built-in
graph, so the assertions passed *by accident* against the bug. It looked like the
test only caught 1 of 7 cases.

Fix: use node ids the fallback cannot imitate (`"11"`, `"12"`, `"13"`). Then the
old code fails 7 of 8 and asserts `"the operator's own graph was discarded"`.
**General rule: when testing a fallback path, the fixture ids must differ from
the fallback's ids, or the test passes on the wrong branch.**

-- the 8 are pre-existing Playwright tests needing a dev server on
`127.0.0.1:8060` (`net::ERR_CONNECTION_REFUSED`), unrelated to this change.
Run them with `scripts/dev-stack.sh` up.

## RexenIOT: live local run + config traps (2026-11-07)

Started the real app on the exposed port and exercised it:
`./.venv/bin/python -m app.main --host 0.0.0.0 --port 12000 --no-browser`
(port 12000 = the `work-1-...prod-runtime.all-hands.dev` host). The venv and the
2.2 GB of cached models in `data/models` **survived the sandbox restart**, so
startup is ~20 s, no re-download.

Working: UI (`/` and `/admin` -> 200, title "Sister RexenIOT"), TTS (real audio:
6.52 s, 24 kHz mono, valid RIFF/WAVE), STT (faster-whisper `tiny.en`, cpu/int8).
Not working here: chat — `localhost:8080` is the *sandbox*, and llama-swap is on
the host, so it fails with "Could not reach the model at
http://localhost:8080/v1/chat/completions". The app reports this cleanly in the
stream and stays up; it is not a crash.

Facts worth keeping:
- **Route paths are NOT what the source suggests.** Routers carry their own
  prefix *and* are mounted under `/api`: `admin.py` is `APIRouter(prefix=
  "/admin")` mounted with `prefix="/api"`, so the real path is
  `/api/admin/personalities/preview`, not `/api/personalities/preview` (that
  returns 405, not 404 — misleading). Enumerate routes, don't guess.
- **`data/config.json` is gitignored local state**, not repo config. Editing it
  does nothing until a restart: `app/config.py` caches the parsed config in a
  module-global `_cache` (`load()` returns it unless `force=True`). Always
  restart after editing, and don't expect the edit to show in git.
- **The model name `qwen3:8` is NOT a typo — I called it one and was wrong.**
  It is the deliberate alias the repo's own `scripts/dev-stack.sh` passes to its
  bundled llama-server (`--alias "qwen3:8"`, line 15), and that script is what
  the app expects to be talking to in this sandbox. The mismatch is
  environmental, not a bug: the *user's* llama-swap names the same model
  `qwen3-8b` (hyphenated, no colon), so against llama-swap the name must change.
  Both names are right for their own server. Do not "fix" the repo's alias.
- Because that change went into gitignored `data/config.json`, it does **not**
  reach the user's machine. On NixOS the authoritative knob is the module's
  `services.rexeniot.llm.model`, which `ExecStartPre` re-applies every start.
- `tts.backend = "torch"` alongside `tier = "nano"` (an ONNX model) is
  **inert, not a bug**: `engine.py` only branches on `backend == "vllm"`, and
  `_resolve_device("auto")` returns `(None, None)` so the library picks the
  provider. Left alone deliberately.
- `api_key = ""` is correct for llama-swap (no auth). `admin_token = ""` means
  the admin API needs no token — fine on a localhost-bound instance.
- `first_run_complete = false` is why the UI may show a setup flow.

## UI for local model detection (app commit 4fdc51f)

Discovery existed only as an endpoint, so a new user still had to know the URL
and model name. Added a **Detect local models** button to the Model Backend card
(`web/admin.html`, `web/js/admin.js::detectLocalModels`). It fills provider,
base_url and model, populates the datalist, and reports the ports it tried when
nothing answers. Read-only; the operator still presses Save.

### Testing browser JS with no browser available

`browser_mcp_browser` fails here: "No browser is connected. Install the Browser
MCP extension". `browser_navigate` fails too ("No browser session active").
So the real `detectLocalModels()` was run in Node's `vm` with a stubbed DOM --
load `web/js/admin.js`, strip the trailing `boot()` call, stub `document`,
`sessionStorage` (NOT just localStorage -- line 9 reads sessionStorage),
`fetch` (rebase to the live server) and `document.createElement` (the `toast()`
helper needs it). Then call the function and assert on the captured node values.
This runs the genuine shipped code path against the real llama-swap: it filled
:8080/v1 + qwen3-8b. Worth reusing whenever the admin UI changes.

### TRAP: REXENIOT_HOME relocates WEB_DIR, so /admin 404s in a test harness

`config.py` sets `ROOT = REXENIOT_HOME or project root` and `WEB_DIR = ROOT/web`.
So `REXENIOT_HOME=/tmp/x` makes WEB_DIR `/tmp/x/web`, `main.py` skips the static
mounts, and `/admin` 404s with `{"detail":"Not Found"}`. This is NOT a bug:
`nix/package.nix` symlinks `$REXENIOT_HOME/web` -> `$out/share/rexeniot/web` on
every start. A test harness must do the same: `ln -sfn <repo>/web $HOME_TEST/web`.
That symlink is guarded (`[ -L ... ] || [ ! -e ... ]`) so an operator's own web/
directory is never clobbered.

### TRAP: the NixOS module overrides the panel on every restart

`nix/module.nix` has `llmSeedApply`, which runs as `ExecStartPre` when
`cfg.llm.baseUrl != null || cfg.llm.model != null`. It jq-merges
`{provider, base_url, model}` into `/var/lib/rexeniot/data/config.json`. So those
three are authoritative on every restart and a panel edit **silently reverts** --
intended (declarative model selection) but a real trap. The user's
`configuration.nix` sets all three, so their panel is effectively read-only for
the model. Documented in README under "When the settings are managed by NixOS".
