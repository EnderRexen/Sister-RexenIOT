# 2026-11-10 - Local-model latency, dead-tool gating, desktop tools

Branch `security/api-token` (off `nix-packaging`). Three changes: stop local
reasoning models burning their budget on a hidden trace, stop offering tools
whose provider is not configured, and add KDE desktop control.

## Reasoning models waste the whole output budget thinking

`app/llm/client.py`. Ollama's qwen3 / deepseek-r1 emit a hidden trace before the
answer. Measured on the RTX 5070: qwen3:8b took 200 completion tokens and 23.1s
to answer a trivial prompt; with the trace off, 13 tokens and 3.1s. At a 200-token
`max_tokens` the 27B model returned *empty* because the trace used the lot.

- The fix is `reasoning_effort: "none"` in the OpenAI-compatible request body.
  On the `/v1` path Ollama ignores `think: false` but honours this.
- `/no_think` in the prompt does nothing on this path. Do not bother.
- `reasoning_effort_for(cfg, provider)` defaults to `none` for a model whose
  name contains qwen3/qwq/deepseek-r1/magistral/glm-z/o1/o3/o4, sends nothing
  for anything else, and returns "" for Anthropic (no such field). An explicit
  `llm.reasoning_effort` wins; the literal `"default"` means "send nothing".
- Applied in both `chat()` and `_stream()`.

## A skill without a provider_field still published its tools

`app/skills.py`. `home` and `images` had no `provider_field`, so
`_provider_configured` returned True unconditionally and their tools were always
offered. On an unconfigured install that is 10 tools (HA, MQTT, ComfyUI) that
can only fail, plus their schema tokens on every turn.

Added `config_fields: list[str]` to `Skill`; the skill is dormant unless **any**
named ToolConfig field is set. `home` -> `["home_assistant_url", "mqtt_host"]`,
`images` -> `["comfyui_url"]`. Offered tools went 23 -> 13 with nothing
configured. Verified by `scripts/test_reasoning_and_gating.py`.

## KDE desktop tools

New `app/tools/app_control.py` + a **Desktop** skill: `notify_user`, `open_app`,
`list_apps`, `control_media`, `set_power_profile`. Verified against the real
session on the host: notification, app list, `open_app kate`, power profile all
worked.

- `_session_env()` harvests `WAYLAND_DISPLAY`/`DISPLAY`/`XAUTHORITY` from a
  plasmashell/kwin PID via `/proc/<pid>/environ`. A systemd unit has none of
  them, so launching a GUI app fails without this.
- **`org.kde.KWin.queryWindowInfo` and `killWindow` cannot work headlessly** -
  KWin implements them as an interactive mouse-click grab, so they hang for the
  full timeout, then raise `org.kde.KWin.Error.UserCancel`. Two tools
  (`active_window`, `close_window`) were written, tested, and removed for this
  reason. Do not re-add without checking upstream.
- `control_media` enumerates `org.mpris.MediaPlayer2.*` on the bus rather than
  naming players. `playerctl` is not installed on the host; `busctl` is.
- `open_app` launches through `systemd-run --user --collect` so the app does not
  die with the request.
- `gdbus`, `xdotool`, `kdotool`, `playerctl`, `pactl`, `kde-open6` are all
  absent on this host. `qdbus`, `busctl`, `wpctl`, `nmcli`, `systemctl`,
  `xdg-open` are present.

## Sandbox quirks that cost time today

- **`/tmp` and the sandbox toolchain are wiped between turns.** The `/tmp/sri-np`
  clone and `/tmp/app_control.py` vanished mid-task, and `ssh`, `paramiko` and
  the tailscaled SOCKS proxy were all gone. Work in `/workspace`, and expect to
  re-run `pip install paramiko` and re-launch tailscaled with
  `--socks5-server=127.0.0.1:1055` (the flag is **not** in `ts-up.sh`, so the
  proxy is refused until it is added).
- There is no `ssh` binary and no root, so `ssh-rexen.sh` cannot run.
  `/workspace/.access/rexen.py` (new) is a paramiko client that CONNECTs through
  the SOCKS5 proxy and reads stdin, so files can be piped:
  `cat f.py | python3 rexen.py --sudo "cat > /tmp/x.py"`.
- The `terminal` tool rejects multiple commands unless chained with `&&`/`;`.
- The installed `rexeniot-full-env` python shadows a test dir; set
  `PYTHONPATH=/tmp/sister-test` and add `__init__.py` files.
