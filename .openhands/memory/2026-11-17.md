# 2026-11-17

## ACE-Step 1.5 music upgrade -- implemented (commit 214a8f2)

Branch `security/api-token`. Music was **broken**, not merely old: the host
ComfyUI (v0.37.0) has every 1.5 core node and none of the v1 pack nodes the
graph was built from, so `/prompt` rejected the graph with
`missing_node_type: 'ACEModelLoader'`. The upgrade is the repair.

### The shape of the fix

- v1 needed `billwuhao/ComfyUI_ACE-Step`; 1.5 runs on **ComfyUI core**, so no
  node pack is needed at all. `KNOWN_NODES` now lists only `manager` and
  `DIR_MODEL_COMPONENTS` is empty.
- Weights are one AIO checkpoint, `Comfy-Org/ACE-Step-1.5`
  `checkpoints/ace_step_1.5_turbo_aio.safetensors` (**10 GB** -- it bundles the
  4B Qwen text encoder). ComfyUI's own 1.5 template names exactly this file.
  Split alternative is ~6.2 GB (0.6b encoder + 4.79 GB turbo DiT + 0.34 VAE).
- **The subtle bug risk:** v1 had two nodes (`MultiLinePromptACES` /
  `MultiLineLyrics`) so the class name distinguished style from words. 1.5
  folds both into ONE `TextEncodeAceStepAudio1.5` node with `tags` and `lyrics`
  fields. `_music_text_nodes()` therefore returns a `(node id, field)` pair per
  target now. Getting this wrong writes the style description into `lyrics` --
  a silent, plausible-looking failure. Both shapes are tested.
- Turbo is step-distilled: `cfg=1.0`, `euler` + `simple`, ~8 steps. At cfg 1.0
  a negative prompt does nothing, so `negative_prompt` is now ignored for music
  (the negative branch is `ConditioningZeroOut`, as in ComfyUI's template).
- `duration` is set on BOTH the text encoder and the empty latent; they have to
  agree. Ceiling raised 240 -> 600 s (1.5's max).
- `[inst]` is still the instrumental marker in 1.5.

### How to validate a graph without the weights

Node classes and input names cannot be guessed. Diff the built graph against the
live server's `/object_info`: every class exists, every supplied input name is a
real input of that class, every link resolves to a valid output slot, every
value is in range or in the combo options. This catches `missing_node_type` and
the subtler "input name the server does not have". `/tmp/validate15b.py` does
this; 8 nodes checked against 1,926 server classes, all valid. The only unmet
requirement left is the weights, which is the honest place to stop.

### On the "comparable to Suno v6" ask

ACE-Step's own README claims 1.5 sits "between Suno v4.5 and Suno v5" -- i.e.
the vendor places it **below** the v6 target. It is still the best open,
commercially-usable option (MIT; YuE2 is CC-BY-NC so unusable commercially).
Do not promise v6 parity; measure it by ear.
