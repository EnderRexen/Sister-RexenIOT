
## 2026-11-04 - API auth hardening (branch `security/api-token`, commit c18c4ff)

The API had no auth on the endpoints that run the agent. Fixed on a branch off
`nix-packaging`.

Root cause worth remembering: `/api/chat`, `/api/chat/stream`, `/api/speak`,
`/api/transcribe`, `/api/uploads`, `/api/status` had no auth dependency at all,
and CORS was `allow_origins=["*"]`. `ADMIN_TOKEN` only guarded admin writes, so
an operator who set it and bound `0.0.0.0` still left the *agent* open.

Design decisions:
- Token: `server.auth_token` / `REXENIOT_API_TOKEN`, header `X-API-Token`.
  `app/security.py` holds `api_token()`, `is_loopback()`,
  `assert_binding_is_safe()`, `require_api_token()`.
- `assert_binding_is_safe()` is called in `main()` before uvicorn starts, and a
  matching `assertions` entry was added to `nix/module.nix`. Both fail loudly.
- `/api/health` and `/api/admin/session` are deliberately open. `/health` is
  polled by `keep-alive.sh` and `dev-stack.sh`; `/admin/session` returns only
  booleans (`requires_token`, `requires_api_token`). Gating `/health` breaks the
  watchdog loops, and gating `/admin/session` stops the admin gate asking
  whether it needs a token. Do not gate these two.
- `dev-stack.sh` polls `/api/health`, not `/api/status` (now gated).
- `keep-alive.sh` still binds `0.0.0.0` because the sandbox preview proxy
  connects from outside the container; it now mints a token to
  `/tmp/rexeniot_api_token` so the exposed bind is authenticated.
- Admin router uses a second `public_router` for `/admin/session`; the rest of
  `/admin` needs the API token *and* the admin token.

Test: `scripts/test_api_auth.py` (47 checks). Plus a sweep over `app.openapi()`
confirming all 66 `/api` route/method pairs return 401 without the token except
the two intended. `scripts/test_wake.mjs` fails on ESM `import` inside
`new Function` - pre-existing, fails on the original `app.js` too.

Env quirk: the sandbox has no fastapi/numpy. Installed
`fastapi uvicorn httpx pydantic numpy psutil python-multipart jinja2` to run
tests. Playwright/onnxruntime/kittenml are absent, so the UI/TTS test scripts
cannot run here.

Untouched: another session had uncommitted work in `app/config.py`,
`app/llm/client.py`, `app/skills.py`, `app/tools/__init__.py` and untracked
`app/tools/app_control.py` (a `reasoning_effort` LLM field + app control). Only
my hunk of `config.py` was staged; theirs is still in the working tree.

## Follow-up: NixOS desktop config (commit 5f03f14)

Wrote `examples/nixos/` (configuration.nix fragment, standalone flake, README)
for the "run it at home over Tailscale" ask.

Key fact, from the Tailscale docs: **`tailscale serve` only supports
`http://127.0.0.1` as a proxy target.** So the loopback bind and the serve-based
remote access are not a trade-off - loopback is the only thing serve can proxy
to. Current syntax: `tailscale serve --bg 8070` (the port alone is accepted as a
shorthand; the documented long form is `--https=443 <target>`). `--bg` persists
across reboots. MagicDNS + HTTPS Certificates must be enabled for the tailnet or
serve has no cert.

`nix/module-check.nix` now also asserts the binding guard fires. NixOS assertions
are only thrown when the system is built, so forcing `config.systemd.services.*`
does NOT reach them; the check reads `config.assertions` directly (a list of
`{ assertion, message }`). Note: evaluating `config.assertions` never throws -
only `config.system.build.toplevel` does.

**Cannot verify Nix in this sandbox.** nix-portable fails with
`symbol lookup error: libc.so.6: undefined symbol: __tunable_is_initialized` (a
glibc mismatch under its proot runtime), and there is no root, so no native Nix.
Validated instead by: tree-sitter parse (all 4 nix files), cross-checking every
option name against module.nix, and mirroring the assertion in Python to check
its truth table. `nixos-rebuild` remains the real verifier.

**Coordination hazard, learned the hard way:** the other session is *actively*
editing `README.md` and `web/admin.html` in this same checkout. `git add
README.md` swept their Desktop-tools section into my index, and `web/admin.html`
was dirty again after my commit. Lesson: before `git add <file>` here, check
whether the file is contested (`git diff <file>`) - stage only if the diff is
100% mine. I dropped my one-line README cross-link rather than keep fighting over
that file; the docs still chain README -> docs/SECURITY.md -> docs/REMOTE-ACCESS.md
-> examples/nixos/README.md.

## Follow-up: remote admin / the sudo trap (commit c08b0dc)

User is **remote from their machine and cannot run sudo**. That is the whole
problem, and it took me several turns to say it plainly instead of iterating on
commands they could not run. Lesson: when the user says they cannot execute
something, stop producing commands and name the actual blocker.

The trap: `tailscale serve` (port forward) needs **no root** (verified in the
serve docs), but `tailscaled` must be running and you must be its operator, and
setting that up is the first root step. So the root-free part is useless until a
root step happens.

Ways out, and the fix that makes one access moment permanent:
- `services.tailscale.authKeyFile` -- connects on boot, no browser login. Without
  it a reboot logs the node out and the machine is stranded.
- `services.tailscale.extraSetFlags = [ "operator=<user>" ]` -- lets that account
  run `tailscale` (incl. `serve`) without sudo. Verified these options exist in
  nixpkgs' tailscale.nix.
- Do NOT advertise a subnet route/exit node: exposes the whole LAN to the tailnet.

Hostname `REXEN-NIXOS-DT` is valid: nixpkgs hostName regex is
`^[[:alnum:]]([[:alnum:]_-]{0,61}[[:alnum:]])?$` (uppercase allowed, lowercase
only *recommended*), and systemd's LDH check uses `ascii_isalpha`. Unquoted
hyphens in attr names parse fine (tree-sitter shows a single attrpath, not
subtraction). Flake attrs are case-sensitive, so `.#REXEN-NIXOS-DT` must match
exactly.

**There is no remote path from the sandbox to the user's machine** -- no SSH key,
no route, no credential. I cannot reach it, ever. Say so early next time.

## One-shot bootstrap (57a62e5, pushed)

User confirmed sshd is NOT running on the box, so there is no existing way in:
the chicken-and-egg case. They have one trip to the keyboard.

`examples/nixos/one-shot.nix` is the single-rebuild bootstrap: sshd (password
auth ON so it cannot lock them out), tailscale with authKeyFile + operator= (so
no later step needs root) + --ssh, and rexeniot on loopback. Supersedes
ssh.nix/remote-admin.nix for this case -- overlapping option sets, don't merge
both.

**I shipped a lockout default in ssh.nix and had to fix it**: it set
PasswordAuthentication = false in the same block that first enables sshd, which
is exactly the failure its own comment warned about. Now defaults to true, with
the tightening commented as a later over-SSH rebuild. Lesson: when writing a
bootstrap config, the default must be the one that cannot strand the operator,
even if it is less secure -- and the comment must match the default.

`nixos-rebuild switch` activates immediately; a reboot is only needed for
kernel/init/boot changes. So "rebuild then reboot" is usually just "rebuild".

Verified: both sshd variants pass real `sshd -t`; bootstrap reports
passwordauthentication yes. All option paths re-checked. `enable` is
`mkEnableOption`, NOT `mkOption` -- a grep for `= mkOption` gives a false MISSING
for enable on any module. Don't be fooled twice.
