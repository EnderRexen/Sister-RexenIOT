    Speech input

    Two ways to capture speech. "On this machine" records a clip in the browser and has the server transcribe it, so the audio never reaches a third party and any browser works. "Browser" uses the vendor's own recogniser, which needs Chrome or Edge. "Automatic" prefers this machine and falls back to the browser when the speech-to-text set is not installed.

    Wake mode

    Keeps the microphone listening for a wake word. Once heard, every utterance is treated as addressed to her until a sleep word is spoken or the session goes quiet. Her own replies are never mistaken for speech, because listening pauses while she talks.

    Wake words are matched loosely, so "hey rexeniot" is heard even when the recogniser splits or runs the words together. Browser speech recognition needs network access; the audio is handled by the browser, not by this server.

    Alexa

    Amazon publishes no API for commanding an Echo or making Alexa speak, so Sister RexenIOT drives a bridge instead. Pick one and fill in its settings; the Alexa skill stays off until a provider is set.

    Voice Monkey and alexacli both use unofficial Amazon interfaces and can break when Amazon changes them. alexacli needs its refresh token re-seeded about every two weeks. Home Assistant's Alexa Media Player is the steadiest of the three.
